# Idea Template

Each idea must be compact enough to compare with other ideas and concrete enough to become an experiment.

```markdown
Idea:
Hypothesis:
Why now:
Signal modality:
Task:
Technical route:
Required data:
Strongest baseline:
Primary metric:
Fastest validation experiment:
Capability fit:
Fatal flaw probe:
Key risk:
Reviewer objection:
Next skill:
Memory candidate:
```

## Ranking Criteria

| Criterion | Strong signal |
|---|---|
| Testability | A cheap experiment can falsify the core hypothesis. |
| Baseline clarity | The strongest baseline is named as a method class, not hand-waved. |
| Data realism | Required modality, split, and pairing are plausible or explicitly missing. |
| Reviewer risk | The idea names likely objections before writing claims. |
| Memory value | A successful session can become a workflow, finding, or eval. |
| Capability fit | Time, compute, data access, expertise, and collaboration needs match the claim. |
| Early-kill value | The fastest validation can falsify the idea before a full system build. |

Do not use this template to invent results. Use it to specify what must be verified.

## Idea Commitment Gate

Before promoting an idea to experiments, check:

- Does the hypothesis fail under at least one cheap, explicit probe?
- Is the closest prior work inspected or explicitly marked missing?
- Would the idea still matter if the strongest simple baseline wins?
- Is the proposed contribution a new capability, a new setting, a better measurement, or only a repackaging?
- Are the user's current resources enough to execute the evidence path?
- What single issue would make a reviewer reject the project?
